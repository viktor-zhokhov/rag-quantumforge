# Задание 1. Исследование моделей и инфраструктуры

## Контекст

Заказчик — **QuantumForge Software** (офис в Хельсинки, разработка в Таллине). Нужен внутренний бот по базе знаний (~21 000 документов, рост +400 страниц/мес).

Три ограничения, которые влияют на выбор:
- компания в ЕС (действует GDPR) — данные нельзя свободно отправлять за пределы ЕС;
- часть материалов конфиденциальна — их нельзя отдавать в чужое облако;
- нужен аудит SOC 2 — бот должен показывать источник ответа.

Цены ниже — примерные (середина 2025 года), для сравнения порядка величин.

---

## 1. Сравнение LLM: локальные (Hugging Face) и облачные (OpenAI / YandexGPT)

LLM — модель, которая пишет финальный ответ.

| Критерий | Локальные (Llama 3.1, Mistral, Qwen2.5) | OpenAI (GPT-4o / 4o-mini) | YandexGPT |
|---|---|---|---|
| **Качество ответов** | 8B — среднее, 70B — почти как GPT-4o | Самое высокое | Хорошее для русского, слабее для англ. техдоки |
| **Скорость** | Зависит от железа | Быстрая, зависит от интернета | Средняя, зависит от интернета |
| **Стоимость** | За токены не платим, платим за видеокарту и обслуживание | 4o ≈ $2.5/$10, 4o-mini ≈ $0.15/$0.6 за 1 млн токенов | Оплата за токены в рублях |
| **Простота развёртывания** | Сложно: видеокарта, настройка, обновления | Очень просто: ключ + HTTP | Просто: API Yandex Cloud |

**Вывод.** Берём две модели: локальную **Llama 3.1 8B** для конфиденциальных данных (не уходят из компании) и облачный **GPT-4o-mini** (регион ЕС) для обычных вопросов — точно и дёшево. YandexGPT не подходит: данные уходят в РФ.

---

## 2. Сравнение эмбеддингов: Sentence-Transformers и OpenAI Embeddings

Эмбеддинг — перевод текста в вектор (набор чисел), чтобы искать по смыслу.

| Критерий | Локальные Sentence-Transformers | OpenAI Embeddings |
|---|---|---|
| **Скорость создания индекса** | 5–10 мс на предложение, интернет не нужен | Зависит от интернета и лимитов API |
| **Качество поиска** | MiniLM — хорошо для англ., есть multilingual-модели | Высокое, `3-large` — один из лидеров |
| **Стоимость** | Бесплатно, платим только за вычисления | `3-small` ≈ $0.02, `3-large` ≈ $0.13 за 1 млн токенов |

**Вывод.** Берём **локальные Sentence-Transformers** (`all-MiniLM-L6-v2`). Причина: чтобы создать индекс, через модель нужно прогнать всю базу знаний. У облачной модели весь текст, включая секретный, ушёл бы на чужой сервер — это запрещено условиями кейса.

---

## 3. Сравнение векторных баз: ChromaDB и FAISS

Векторная база хранит эмбеддинги и находит самые похожие.

| Критерий | **FAISS** | **ChromaDB** |
|---|---|---|
| **Скорость поиска и индексации** | Очень высокая, работает внутри программы | Высокая, упирается в объём памяти |
| **Сложность внедрения и поддержки** | Минимальная: `pip install` и 5 строк кода | Низкая, хорошо дружит с LangChain |
| **Удобство в работе** | Нет фильтров и метаданных из коробки | Есть простые фильтры и метаданные из коробки |
| **Стоимость владения** | Бесплатно, отдельный сервис не нужен | Бесплатно |

**Вывод.** Наш объём (~150–300 тыс. кусков-чанков) целиком влезает в память сервера, поэтому сложная база не нужна. Берём **FAISS**: он самый быстрый и простой, работает локально (данные не уходят). Метаданные (источник, дата) храним рядом в файле и фильтруем после поиска.

## 4. Конфигурация сервера

| Компонент | Что нужно |
|---|---|
| Эмбеддинги (Sentence-Transformers) | Обычный процессор (видеокарта только ускоряет) |
| Индекс FAISS | 0,5–3 ГБ памяти + процессор |
| Локальная LLM 8B | Видеокарта на 24 ГБ (RTX 4090 / A10) |

**Итого для MVP:** сервер с процессором (8+ ядер) и 16–32 ГБ памяти. Видеокарту на 24 ГБ добавляем, когда подключаем локальную LLM. Разворачиваем в Docker.

---

## 5. Итоговые варианты и рекомендация

| | A. Всё в облаке | B. Эмбеддинги локально, LLM в облаке | C. Всё на своих серверах | **D. Смешанный (выбор)** |
|---|---|---|---|---|
| **LLM** | GPT-4o | GPT-4o-mini | Llama 3.1 70B локально | GPT-4o-mini + Llama 3.1 8B локально |
| **Эмбеддинги** | OpenAI | Локальные | Локальные | Локальные |
| **Векторная база** | Pinecone | FAISS | FAISS | FAISS |
| **Приватность** | ❌ база в облаке | ⚠️ частично | ✅ всё внутри | ✅ секретное локально |
| **Стоимость** | Высокая | Низкая | Высокая (видеокарты) | Низкая–средняя |
| **Сложность запуска** | Просто | Просто | Сложно | Средне |
| **Подходит под кейс** | ❌ | ⚠️ | ✅ дорого | ✅ баланс |

**Рекомендация — вариант D:**
- **Векторная база — FAISS**: локально, бесплатно, быстро, минимум настройки.
- **Эмбеддинги — локальные Sentence-Transformers**: вся база остаётся внутри компании.
- **LLM — две модели**: GPT-4o-mini (ЕС) для обычных вопросов + локальная Llama 3.1 8B для секретных.
- **Сервер**: процессор 8+ ядер, 16–32 ГБ памяти; видеокарта 24 ГБ под локальную LLM.

**Почему так:** решение соблюдает ограничения кейса (GDPR, конфиденциальность, SOC 2), стоит недорого и просто запускается.

> Для проектной работы (Задания 2–5) используется **FAISS**.
